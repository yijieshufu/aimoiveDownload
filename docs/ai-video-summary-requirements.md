# AI 视频总结需求分析文档（最终确认版 v3）

## 一、已确认项（来自你的最终确认）

1. 自动语言判断范围：**中文优先（中）**
2. 英文内容支持“一键翻译中文”：**是**
3. 导图是否允许删除主分支：**是**
4. 导图自动保存防抖：**是（600ms）**
5. Q&A 上下文范围：**仅当前任务**
6. 标签最小保留：`**Summary` 与 `Mindmap` 必有**

## 二、产品目标

构建一个双栏工作台，围绕“一个视频入口”完成解析、下载、总结与导图编辑闭环：

- 左侧：视频地址输入、解析信息、清晰度选择、下载
- 右侧：AI 总结工作区（Summary / Chapters / Timeline / Transcript / Mindmap / Q&A）
- 要求：可编辑、可保存、可恢复

## 三、功能范围

### 1) 视频处理

- 单入口粘贴视频地址并解析
- 展示可下载格式并发起下载
- 保留现有下载能力与安全下载接口

### 2) AI 总结（异步任务）

- `POST /api/summarize` 创建任务
- `GET /api/summarize/{task_id}` 轮询进度与结果
- 展示阶段进度条（如：URL 处理/转录/LLM/Markdown）
- 用户在**视频解析结果页**点击「**AI 总结**」按钮，触发 AI 分析（与当前解析 URL 绑定）

### 2.5) AI 能力（DeepSeek + SSE 流式输出）

- AI 能力：接入 **DeepSeek** 大模型（兼容 OpenAI Chat Completions 协议）
- 输出形态：支持 **SSE 流式输出**，实时展示生成过程
- SSE 事件类型（建议）：
  - `stage`: 阶段变更（extracting_transcript / calling_llm / rendering_markdown 等）
  - `delta`: 文本增量（用于前端实时渲染）
  - `progress`: 进度（0-100）
  - `done`: 最终结构化结果（JSON）
  - `error`: 错误信息（可读）

### 3) 总结展示结构

默认系统标签（可编辑顺序与名称）：

- Summary（必有）
- Chapters
- Timeline
- Transcript
- Mindmap（必有）
- Q&A

总结内容要求：

- AI 自动生成：**视频概述、内容大纲、核心知识要点、一句话总结**
- 结构化输出、去重、去噪、时间戳纠正
- 重要度排序
- 支持 Markdown 下载
- 使用 `@tailwindcss/typography` 对 Summary 区域进行精美排版（prose）

### 4) 语言策略

- 不固定中英，按内容自动判断
- 当识别到英文内容时，支持“一键翻译中文”
- Q&A 默认跟随当前总结主语言

### 5) 思维导图（XMind 风格）

- 可编辑：新增子节点、新增同级、重命名、删除、拖拽
- 允许删除主分支（root 下一级）
- 自动保存：编辑后 600ms 防抖保存
- 刷新/重开恢复最近保存版本

结构与质量约束：

- 主分支数量 4-8（模型输出后按规则归一）
- 最大层级 4
- 同级去重与排序（重要度 + 时间）
- 渲染前清洗异常节点（空名、纯符号、坏层级）

### 6) Q&A

- `POST /api/summarize/{task_id}/qa`
- 仅使用当前任务（当前视频）的总结与转录作为上下文
- 不做跨任务检索
- 支持多轮对话（同一 `task_id` 保存对话历史）

### 6.5) 字幕/转录（时间戳列表 + 下载）

- 字幕文本：展示带时间戳的完整字幕列表
- 支持展开/收起（默认折叠为“按段落/按时间块”）
- 支持下载字幕文件三种格式：SRT / VTT / TXT

字幕获取策略（必须）：

- 优先提取平台自带字幕（人工字幕 > 自动字幕）
- B 站：通过专用 API 获取 CC 字幕（优先人工）
- 无平台字幕时：回退 ASR（faster-whisper）

## 五点五、思维导图视觉与结构规范（按参考图新增）

当前导图效果不达标，后续实现必须对齐你提供的参考样式（中心辐射、彩色分支、紧凑排版），具体标准如下：

### 1) 布局形态（必须）

- 采用 **中心主题 + 双侧辐射** 布局，不允许出现大量空白和孤立括号状元素
- 根节点居中显示，一级主干均匀分布在左右两侧
- 画布首次渲染时自动执行紧凑布局（compact），减少节点漂移与断层
- 缩放默认适配到可视区域（fit to view）

### 2) 层级与信息密度（必须）

- 一级主干：4-8 个
- 二级分支：每个一级主干 2-6 个
- 最大深度：4 层
- 同级节点去重，禁止空节点、纯符号节点（如 `(`、`)`、`[]`、`{}`）
- 当模型输出过散时，自动合并弱相关叶子节点，避免“满屏碎片标签”

### 3) 视觉风格（对齐参考图）

- 一级主干使用不同色系（如橙/红/绿/蓝/紫），增强主题分组识别
- 连线采用平滑曲线，主干线条略粗于子分支
- 节点样式统一为圆角卡片（非按钮堆叠感）
- 文本优先单行；超长自动省略并支持悬浮查看完整内容
- 根节点视觉权重最高（尺寸/字重/边框明显高于其他节点）

### 4) 文本与命名规范

- 节点名称应为“短语”而非长句
- 中文节点建议不超过 12 字，英文不超过 24 字符
- 一级主干命名优先“主题词”，二级分支优先“方法/结论/注意点/场景”
- 统一语言跟随总结语言；英文内容支持一键翻译中文后同步更新导图文案

### 5) 交互体验（必须）

- 支持：新增子节点、新增同级、重命名、删除、拖拽
- 支持：展开/折叠分支、居中到选中节点、缩放
- 支持：全屏展示
- 自动保存：编辑后 600ms 防抖提交
- 保存状态可见：Saving / Saved / Failed
- 刷新后恢复最近编辑版本（不是初始模型版本）

导出能力（必须）：

- 支持下载 **SVG 矢量图**
- 支持下载 **高清 PNG（4K+）**

### 6) 验收标准（导图专项）

- 不再出现“括号状噪点”与孤立无效节点
- 首屏导图可读，结构接近参考图的“中心辐射+分组色彩”效果
- 主干与子分支层级清晰，无严重交叠或大面积空白
- 编辑任意节点后可自动保存并在刷新后恢复

### 7) 参考依据（公开资料归纳）

以下规则来自对公开产品资料的归纳，不是照搬某一款工具，而是提炼为本项目可执行标准：

- XMind 设计原则：强调 **Proximity / Alignment / Contrast / Repetition**，用于提升导图可读性与一致性
- XMind 结构建议：中心布局下要保证层级对齐、主次对比、样式重复一致，避免视觉噪声
- Coggle 自动整理思路：提供 auto-arrange 能力，说明“布局自动整形”是导图产品的基础能力

本项目落地对应关系：

- `Alignment` -> 首次渲染自动 compact + fit-to-view + 居中根节点
- `Contrast` -> 主干分支颜色区分、层级字重区分、主干线条更粗
- `Repetition` -> 同层统一节点样式（圆角、间距、字体规则）
- `Auto-arrange` -> 提供“自动整理布局”操作入口（后续迭代加入按钮）

## 六、交互与体验要求

- 右侧工作区在解析完成后可用
- 标签支持新增、重命名、删除（受“必有标签”规则约束）、排序
- 导图面板提供常用操作按钮（增/删/改）
- 进度条与保存状态有明确反馈

## 七、验收标准

1. 可完成“解析 -> 下载 -> 总结”闭环
2. 总结结果结构稳定、可读性提升
3. 标签配置刷新后仍保留，且 `Summary`/`Mindmap` 始终存在
4. 导图编辑自动保存，刷新后恢复最近版本
5. Q&A 仅基于当前任务上下文回答
6. Markdown 下载可用
